# Plan 03 — `UserPromptSubmit` hook: stdin JSON, JSON stdout, silent fail

## Objective

Implement the Claude Code `UserPromptSubmit` hook script: read the hook event from stdin (JSON line or full payload per Claude’s format), expand `{{tagname}}` in the submitted prompt using `lib/expand.cjs` + `lib/macros-store.cjs`, emit **only** successful JSON stdout per **D-04**; on any failure, log via `lib/error-log.cjs`, exit **0**, stdout empty (**D-05**). For each missed tag, append **warn** JSONL (**D-06**, **EXPN-03**).

<threat_model>
## Trust boundaries

| Boundary | Description |
|----------|-------------|
| stdin (hook event) | Untrusted size/content; could be malformed JSON or hostile strings. |
| `macros.json` | Untrusted data; parsing must not crash the process. |
| stdout | Must be valid JSON only on success path — Claude Code parses it. |

## STRIDE register

| ID | Category | Component | Disposition | Mitigation |
|----|----------|-----------|-------------|------------|
| T-03-01 | D | Huge stdin / prompt | mitigate | Cap read size reasonably (e.g. readline first line only if protocol is line-based); document assumption matching Claude Code hook payload size. Prefer `readFileSync(0, 'utf8')` with max length guard if needed. |
| T-03-02 | E | stdout corruption | mitigate | On success, single `JSON.stringify` + newline; no `console.log` debug in production path. |
| T-03-03 | T | Malicious `macros.json` | mitigate | Wrapped `readMacrosSync` try/catch → log `error` line, pass-through prompt. |
| T-03-04 | I | Fake expansion | accept | Local user controls macros; threat model is same-user. |
| T-03-05 | S | Prompt injection via macro value | accept | User owns macro values; document risk in manual setup (Phase 1). |
| T-03-06 | R | N/A | accept | Local only. |
</threat_model>
